# Accessibility

HESI–5P is intended to be usable by people with different disabilities, access needs, languages, devices and levels of technical knowledge.

## Our approach

Repository documentation aims to:

- use plain English and short, direct sections;
- explain specialist terms and abbreviations;
- use predictable headings and descriptive links;
- provide alternative text for informative images;
- provide text explanations for complex diagrams;
- avoid relying on colour alone;
- use simple tables with labelled columns; and
- remain readable on mobile devices and at high zoom.

Where applicable, the project uses [Web Content Accessibility Guidelines 2.2](https://www.w3.org/TR/WCAG22/) as a reference. This statement describes an improvement goal; it is not a formal claim that every GitHub interface or project file conforms to a particular WCAG level.

## Current content alternatives

The AI and quantum-computing infographic in the README is supported by the text-based [AI + Quantum Computing Working Together](docs/case-studies/ai-quantum-computing.md) case study.

Mermaid diagrams are also explained by the numbered steps and surrounding text. Readers should not need to interpret an image or colour to understand the core model.

## Reporting a barrier

If part of the repository is difficult to read, navigate or understand, open a GitHub issue beginning with `Accessibility:` and include:

- the file or section;
- the barrier you encountered;
- your device or assistive technology, if you are comfortable sharing it; and
- the alternative format or improvement that would help.

Do not include private medical information. You may describe the access barrier without naming a diagnosis.

Accessibility corrections should be treated as substantive quality improvements, not cosmetic changes.
